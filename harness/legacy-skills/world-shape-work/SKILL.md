---
name: world-shape-work
description: Shape an authorized Herdr World feature or ambiguous backlog item into user outcomes and acceptance criteria.
---

Read the owner's objective, current contracts and relevant source via docs/knowledge-map.md.
Identify the intended user outcome, scope, non-goals, observable acceptance and material
unknowns. Use supplied research or inspect primary evidence; label assumptions and do not
invent user feedback. Prioritization stays within the authorized roadmap and constraints.

Reuse the coherent OpenSpec change when a requested spec or new contract needs one.
Ordinary fixes need no product phase or proposal. In the Ralph product role, return the
structured acceptance and summary; the source mount is read-only and the implementer owns
durable edits. Do not duplicate OpenSpec in a separate PRD database. Existing permission
carries through the workflow; ask only for consequential decisions that cannot be inferred.
