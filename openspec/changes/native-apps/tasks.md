Design approved before any task starts (#1400). Each task lands with its tests. If a
spike shows the design cannot hold, the design returns for review before 2.x.

## 1. Prove the risky parts first

- [ ] 1.1 Android spike in `apps/native/` (Tauri ≥ 2.11.1, target SDK 36): plugin-owned World web view on its own `androidx.webkit` profile per World; two synthetic Worlds on one host at different ports keep separate sessions; the profile's `CookieManager` returns World's HttpOnly cookie; Forget with `deleteBrowsingData` + `removeAllCookies`, then `deleteProfile` at the next process start, leaves the other World signed in and no cookie, storage, cache or service worker of the forgotten one; the "Update Android System WebView" screen when `MULTI_PROFILE` or `DELETE_BROWSING_DATA` is missing; pairing view replaced by a fresh view, then `copyBackForwardList` (URL and original URL) and the data folder hold no token, also after restart; a `specialUse` service holding a stream with the activity closed, after process death and after reboot; cross-origin form `POST` refused by `shouldInterceptRequest` with no request sent, a World-origin `307` to another origin returned to the World by `onPageStarted` with the fixture beacon showing whether its script ran; the saved last event ID resumes the stream after the process is killed; the signed arm64 APK installs and runs on an x86_64 API 35 emulator image with ARM translation (else switch to a universal APK); APK size. Record results here before 2.x.
- [ ] 1.2 Desktop spike (Windows, macOS 14, Linux): per-World `data_directory` / `data_store_identifier`; `cookies_for_url` and single-cookie deletion; two same-host Worlds keep separate sessions; Forget removes the store (`remove(forIdentifier:)` on macOS, folder delete after releasing WebView2/WebKitGTK) or defers it to next start; pairing view replacement leaves no token in history or the data folder; capability scoped to the `list` web view and custom commands in `AppManifest`, World pages refused; `on_navigation` and `on_new_window` policy, including a cross-origin form `POST` and a `307` on each engine; notification `on_action` opening a hash; installer sizes.
- [ ] 1.3 All-in-one spike (macOS 14 arm64, Windows, Linux `.deb` and AppImage): the release archive's `herdr-world` as a sidecar, byte-identical and placed off `PATH` (`.deb`); `service install --host 127.0.0.1` from the bundled path, World running at login and after the app quits; detection of a running World, a service definition and a standalone installation from the same archive; an unnotarized, quarantined `.dmg` after Open Anyway: may launchd run the bundled World?; Tauri updater with a throwaway key: macOS `.app.tar.gz`, NSIS hooks ending and restarting World's task on Windows, AppImage re-extraction and `service install`; agent terminal still present after the update. Record results here before 2.x.
