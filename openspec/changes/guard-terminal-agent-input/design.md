## Context

A terminal can outlive the agent that asked. Text prefixes do not make shell input safe. The owner's 2026-11-28 decision supersedes the earlier session matching, child analysis and PTY reader designs.

## Decisions

1. One shared check classifies only the runtime-reported foreground process group's leader by executable basename, ignoring arguments. It refuses shells, REPL interpreters, editors/pagers, ssh, sudo/su, database clients, tmux/screen/zellij and docker; other basenames deliver. Thus node/python script launchers are classified by their interpreter basename too.
2. Ignore children and MCP helpers. Remove all tty-reader code and input-specific /proc inspection. Existing topology discovery is unchanged and is not used by input admission.
3. TUI resolves the exact pane and selects the process whose PID equals the reported foreground group ID. Core uses terminal.get's foreground leader immediately before native input. Missing foreground information, including unsupported TUI process-info calls, skips this additional check and preserves prior behavior on macOS and remote hosts.
4. Existing immutable connection, generation and terminal qualification still apply. Explicit owner Terminal input retains its authority. A refused answer remains saved, is never automatically revived and offers Not sent, Copy answer, ask get and draft-only Terminal recovery in Reception.
5. Follow-up #1447 keeps peek reply/menu and review-prefill encoding on `pane.send_input` with an explicit `agent_input: true` marker. World's dispatcher consumes the marker and opts into the existing server-side guard at the last TUI input boundary. It never forwards the marker to Herdr. This does not enable those TUI-only raw methods on core; core retains its guarded Chat/native paths. Direct Terminal input is unchanged. Refused peek replies offer Not sent and Copy in every view using the shared sender; review prefill retains its draft and offers Copy feedback. Neither fallback types or retries. No new World state or storage is needed.
6. Follow-up #1451 replaces the blanket refusal of recipients captured by an earlier World run with a lazy proof at every resolve (answer recording, dispatch fence and final input guard). Herdr TUI must show the same connection, pane, terminal and harness-reported session before and after the foreground check, with the conversation scheme and session fingerprint unchanged; `conversation.send` rechecks the fingerprint just before input. herdr-core reports no session ID of its own, and PIDs and executable names can be reused by another session (review of PR #1477 reproduced a replacement `claude --resume <other>` on reused PIDs). So a core recipient records `session`, the `coreSessionProof` hash of core ID, address, terminal creation time, harness name and the session UUID the foreground program names (Claude `--session-id`, `--resume`, `-r`, refused with `--fork-session`; Codex `resume <uuid>`). Across a World restart only an equal current hash proves the asker, so `claude --resume <original>` in the same terminal qualifies even as a new process; only then is a recycled connection generation accepted. A program that names no session, or a recipient saved before this field existed, stays Not sent, which is safe. The occupancy fingerprint is not used because it holds a per-run counter. Legacy core-token recipients stay refused. A generation change within one World run is unchanged. Herdr TUI derives its proof from runtime facts at check time and stores nothing new.

## Evidence and limits

Isolated synthetic World/core/TUI transports and real World storage cover an agent exiting to bash before answer, dispatch and final input, with zero writes, Not sent and ask get retrieval on both runtimes. Finite executable/path matrices cover denied leader categories, ignored arguments and children, and missing-information compatibility. Existing runtime/effect models retain generation and opaque-recovery state spaces; the full verification gate remains required for changed contract owners. No new ordering model is needed for this stateless predicate.

A shell started inside a live harness is deliberately outside this check. A runtime without foreground information behaves as before this PR. Neither runtime makes the final OS foreground check and typing atomic; no live-platform or exactly-once guarantee is claimed.

The #1447 request/foreground matrix runs real qualified dispatch on isolated TUI transports with admitted and refused leaders, stale/absent agent labels, submit/prefill/menu input, retired generations and revoked browsers. Caller tests require the marker; desktop and phone browser checks exercise review refusal, retained concurrent edits and Copy without input. Existing core guard matrices remain applicable. This adds a stateless admission opt-in, not a new scheduling/recovery state; the full gate retains existing authority and recovery evidence. `?agentInputGuard=refused` is a testing-only, immediately removed page switch: these two paths refuse before any runtime call until reload, so preview recovery can be tried without changing a live agent.

The #1451 matrices capture recipients under an earlier synthetic World run and answer before or after the restart on isolated TUI and core transports: the same session delivers once, and on core so does `claude --resume` of it as a new process; a replaced session (on core one reusing the PIDs and name), a program naming no session, or another harness types nothing, keeps ask get, and does not replay after later wakes. Effect-level tests cover every pre-restart phase, including uncertain dispatches and an explicit duplicate decision. `?answerContinuityFixture` is a testing-only, immediately removed page switch showing the same outcomes in Town > Reception > Outbox with synthetic agents and no runtime calls.
