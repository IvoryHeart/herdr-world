## Context

See [proposal.md](proposal.md) for the user outcome and the [World surfaces contract](../../specs/world-surfaces/spec.md) for current ownership. The shared shell mounts Spaces continuously and suspends its visible terminal presentation when a visual view owns that terminal. `WorldFoundationApp` retains up to one docked plus five floating Inspector conversations. A Tree docked Inspector can be portalled into its leaf. Floating geometry is saved per connection and World node. The tab bar is common to every view.

Today `App` renders the active Herdr tab's full `pane.layout` in Spaces, while `WorldTerminalPortalList` mounts one `TerminalView` for an Inspector's selected pane. The focused store fetches only the active tab's layout. Conversation identity is a World pane node, so sibling panes can currently create separate Inspectors. The Spaces tab strip already lists all open tabs in the focused workspace, but its stage shows only the active one. Its workspace Inspector is a separate singleton and can retain an origin pane after focus changes. `terminalPresentationTarget` currently gives a Spaces Inspector on Terminal priority over the stage pane, so a simultaneous tab window and Inspector Terminal would conflict. Roamgate's current tab bar and application expose pane splitting and resizing, without window arrangement controls. Herdr remains authoritative for pane topology and geometry; this change owns only browser presentation.

## Goals / Non-Goals

**Goals:**

- Give Spaces, Office, Tree and Graph one predictable, reversible arrangement command. Spaces arranges existing tabs of its focused workspace; visual views arrange Inspector windows already open, including the docked or inline Inspector.
- Make the current one-tab Spaces presentation a Single arrangement and keep its one Inspector bound to the active tab and selected pane.
- Make a Herdr tab the unit of terminal presentation in an Inspector while keeping selected-pane identity for its header and pane/agent-specific resources and retaining valid workspace or checkout resources.
- Keep qualified terminal attachments singular and ensure window moves, view handoffs and splits refit to their real containers.

**Non-Goals:**

- Creating Herdr tabs, panes or sessions as an arrangement side effect, changing Herdr's split tree, opening more than the existing visual Inspector limit, or introducing server layout state.
- Exposing simultaneous windows on compact layouts or changing terminal transport.
- Adding a new dependency, WebSocket, SSH connection or terminal renderer.

## Decisions

### Separate Inspector window identity from selected pane

Use a live qualified terminal-window key of connection ID, runtime generation, workspace ID and Herdr tab ID. Keep the currently selected pane and its World node as changeable conversation context. A space Inspector keeps its qualified space key. Selecting a sibling pane finds the tab window, focuses it in its existing presentation, and changes selected pane and applicable resource tabs. Focusing a sibling *inside* the split Inspector makes the same context change; terminal focus and the Inspector header/resources must agree. This preserves one window per tab and prevents two windows from presenting the same terminal pane. Its connector and compact identity follow the selected pane's World node. When that pane closes, choose a remaining pane in the same observed tab; retire the window when the tab or lease disappears. A pane that moves to another tab is re-resolved against current ancestry, never silently rebound by a reused native ID.

Files uses the workspace's resource scope, which may identify a checkout; ordinary Changes uses the workspace ID. Sibling focus within the same workspace keeps valid Files and ordinary Changes mode, selections and replies, subject to their existing workspace/checkout and connection lease fences. Today `WorldFoundationApp` keys `WorldInspectorConversationView` by node and `resourceIdentity`, and `WorldInspectorConversationView` resets `changesScope` when `resourceIdentity` changes. Use the stable live tab identity for the Inspector component and preserve workspace-scoped state through sibling focus; reset only state whose pane or agent session owner changed. Agent checkout Changes and History capture pane and session identity. A sibling selection, whether from a World view, navigator or inside the Inspector, updates the header and resource applicability and rejects agent-specific replies or selections that no longer match the selected pane and session. A late result for pane A must never appear as pane B's agent data.

The alternative of keeping one window per pane would allow two sibling Inspectors to attach the same split tab and require hiding panes in one or both windows. The chosen tab key matches the user's requested split presentation and terminal ownership invariant.

### Render tab layouts through one reusable terminal presenter

Extract the Spaces pane-layout rendering behavior into a tab-scoped presenter that accepts a validated `PaneLayout`, current panes, selected pane and destination. Spaces Single supplies its active layout; its other visible tab windows and each visible Inspector Terminal supply layouts for their own tabs. Fetch non-active tab layouts through the existing read-only `pane.layout` call using a pane in that tab. Revalidate connection, generation, workspace, tab and pane membership against the focused store before publishing a result. Refresh a visible tab after split, close, move, zoom or resize events; cached geometry may bridge a same-membership refresh but must never make stale topology actionable. Limit requests to visible Spaces tabs and open terminal-capable Inspector tabs and reuse the existing connection lease.

Keep one portal owner per qualified terminal pane across Spaces and Inspector destinations. A tab window may contain several owners, but a pane has exactly one current destination; handoff detaches from the previous destination before attachment to the next. While Spaces is visible, each presented tab window owns the panes shown by its Herdr split or zoom layout regardless of the Spaces Inspector resource selection. Hidden Single-mode tabs and hidden visual Inspectors do not retain a competing terminal attachment. Refitting happens after geometry or destination changes. Pane focus and input remain routed through the existing qualified store and terminal gate. A shared tab presenter is needed because the store's single active `layout` cannot represent multiple open tab windows at once.

### Use one shell-level arrangement command and pure geometry resolver

Put the arrangement icon at the right edge of the desktop tab bar, where it remains discoverable as tabs grow. On mobile, put it inside the existing ellipsis-expanded floating controls instead of adding a separate floating icon or forcing a one-tab strip to remain visible. The arrangement choices still follow the compact single-window presentation rule.

Reuse the same arrangement control in the Roamgate-derived shell Actions command menu across Spaces and visual views. The shell menu lists window placements separately from entity actions, so a missing or retired selection disables only target-specific actions. Keep the shell's existing shortcut defaults and numbered Actions order. Arrangement shortcuts are configurable but unassigned by default; when a user assigns one, the shell routes it to the active view's arrangement control and ignores it when that placement is unavailable or a dialog/menu owns the keyboard. The menu, Actions and optional shortcuts share the resolver and Restore snapshot instead of maintaining separate placement logic.

Office, Tree and Graph retain the shell's right-side Actions command menu with its original workspace, tab, pane, file and agent commands. Add their qualified visual actions, arrangements, Pin, Unpin, Pinned only and watch status as groups in that same command menu; do not substitute a second visual menu. This keeps search clear and the top bar at one Actions control. Keep the selected-host/runtime summary in the top bar as a muted indicator with full counts in its accessible label and tooltip.

Pass the current view and an arrangement callback from `WorldFoundationApp` through `App` to the shared `TabBar`. The control is one icon with a labelled menu and small layout previews. It offers Single, Cascade, Columns, Rows, Grid and Restore positions; Single uses a single-rectangle icon and means one active tab/window fills the available stage, avoiding the ambiguity of browser fullscreen. The callback snapshots the current view's eligible qualified windows and makes no Herdr mutation call. Spaces derives windows from the focused workspace's already open Herdr tabs. Office, Tree and Graph derive windows from visible Inspector conversations. Invisible retained World Inspectors are not arranged while Spaces is active, and Spaces windows are not arranged while a visual view is active. This is one arrangement feature with two adapters to existing window sources, not separate view-specific layout algorithms.

Resolve each preset from the actual stage rectangle, current window count, focus order and minimum usable dimensions for that window type. Use one pure resolver for Single, Cascade, Columns, Rows and Grid. Single presents the active window over the available stage and suspends the terminal presentation of other retained windows. It does not change Inspector admission: ordinary selection of B while A is docked still closes A before B is mounted, while other open floating conversations remain retained and count toward the existing limit. A tab-strip selection in Spaces changes the active Single window; a World selection in a visual view follows those existing dock and floating rules. Restore never recreates a docked conversation closed by selection. Disable a preset atomically if it cannot satisfy its nonoverlap or reachability rules. Grid uses two columns for two windows, one full-height column plus two stacked for three, and four corners for four or more. Above four, remaining windows keep reachable floating geometry above the four tiles. Cascade offsets windows in z-order and exposes each older title. Use browser viewport coordinates only at the DOM boundary; the resolver takes rectangles in one coordinate system. Do not cap Spaces tabs to the visual Inspector limit; if a preset cannot keep every eligible window usable, disable it and explain why.

Keep default floating, normal minimum, Spaces tab-window minimum and compact tiled minimum sizes together in `floatingTerminalGeometry.ts`. Cascade uses the default floating size fitted to the stage and diagonal offsets, rather than stretching each window to the remaining stage. Columns and Rows use equal tile sizes and may shrink below normal floating minimums, down to the compact minimum that keeps the controls usable. Explicit resize of a compact tile retains that smaller minimum; ordinary free windows keep their normal minimum. The option remains unavailable if even the compact minimum cannot fit all current windows.

Pane-selection controls expose their target pane ID to the Inspector's native pointer-capture focus handler. The handler skips its old-pane focus when a split cell, mobile switcher button or zoomed pane will select another pane. That leaves one focus request for the pointer action and prevents out-of-order browser-local `pane.get` replies from changing the user's chosen pane.

The alternative of separate per-view geometry logic would diverge as the user moves among Spaces, Office, Tree and Graph. A persistent multiwindow auto-tiling mode would also reposition later opens, contrary to the chosen one-shot behavior. Single is an active-window presentation and follows focus, including a newly opened tab or an Inspector admitted by the existing dock/floating rules. It is the default Spaces presentation; choosing another preset creates only browser window presentations for tabs that Herdr already has open.

### Keep the Spaces Inspector on the active tab

The one Spaces Inspector remains outside the terminal-window set. Its workspace scope remains qualified, but its selected pane context follows the active tab and focused pane as the user selects a tab, focuses a tiled window or focuses a sibling in that window. Its header and agent checkout Changes and History applicability follow that pane and session; late agent-specific replies for a prior tab or pane are discarded. Valid Files state remains scoped to the workspace or checkout, and ordinary Changes state remains scoped to the workspace, across sibling or tab focus in the same workspace. When Terminal is selected, the Inspector keeps that resource tab selected but shows a non-attached status and a keyboard-accessible **Focus tab window** action for the active tab. The tab window displays and owns its Herdr split or zoom layout in both Single and multiwindow arrangements; the action focuses the active tab's selected pane without creating a tab or terminal attachment. This replaces `terminalPresentationTarget`'s present Inspector-first Spaces behavior and avoids a second live owner or a missing pane in the arranged window. The Inspector dock consumes stage space when visible, so the arrangement resolver receives the actual remaining stage rectangle. A terminal focus does not create or focus a visual-view Inspector.

### Treat docked and inline Inspectors as arrangement participants

Keep each Inspector's dock membership and resource state in the conversation registry. An arrangement gives the docked Inspector temporary free geometry. In Tree, temporarily portal the inline Inspector into a shell overlay at that geometry, retaining its exact leaf as the return target. Do not clone its content or terminal owner. Capture each participating instance's prior geometry and dock/inline presentation before its first arrangement; later presets retain that baseline. Restore positions returns still-open instances to those captured targets. New instances do not inherit the arrangement; closed instances are not resurrected. An explicit dock-position action clears the temporary geometry for that Inspector.

This is more involved than tiling only floating windows, but it is necessary for the requested all-visible-Inspector behavior and avoids an apparently broken control when a docked window is on screen.

### Keep desktop geometry across compact and view transitions

The visual stage is measured with `getBoundingClientRect`, while floating Inspectors use fixed-position CSS coordinates. Convert the measured rectangle into those coordinates using the same runtime fixed-position scale probe as shell popovers before resolving placements. This keeps the intended top and bottom insets balanced when CSS UI scaling changes the coordinate ratio.

Arrangement coordinates belong to the current desktop stage and are clamped when that stage changes. Moving to Spaces suspends visual Inspector presentation and retains its geometry without arranging hidden windows; returning to a desktop visual view restores or clamps that arrangement. Spaces retains tab-window placement separately for each focused workspace while the visual views or another workspace are active; changing workspaces detaches the old workspace's terminal windows. Compact mode shows one active window and must not overwrite saved desktop placement with its full-screen compact bounds. Existing per-window browser geometry remains local presentation state. Keep the live Inspector tab-window key generation-qualified, but save its geometry under the stable connection/workspace/tab key without runtime generation. Read an old pane-key entry once when available, then write the stable tab key; a reconnect must recover the last saved Inspector position instead of falling back to an older pane position. Spaces tab-window arrangement positions stay session-local and do not overwrite Inspector geometry for the same tab. Arrangement baseline is session-local because windows themselves are not restored across browser reloads.

## Risks / Trade-offs

- **Many windows cannot tile at ordinary desktop sizes** → disable infeasible Rows, Columns or Grid options with a clear reason; Single and manual placement remain available. Cascade is available only when its title reachability constraints fit.
- **A Tree inline portal can remount a terminal during arrangement** → transfer the same owner to a temporary overlay and test exact attachment count, focus and restore to the original leaf.
- **Additional floating windows obscure part of a Grid** → keep every header reachable, preserve free geometry and frontmost order, and leave all four tiled window headers accessible for raising; disable Grid when that cannot be achieved.
- **Tab grouping changes the current pane-based Inspector behavior** → retain pane-specific header/resources and exact selected-pane focus while giving the tab one stable window.
- **Spaces Inspector Terminal currently owns the selected pane** → transfer presentation to the tab window when Spaces is visible, show a focus affordance in the Inspector, and test Single and multiwindow modes with a split tab and one attachment per pane.
- **Background layout replies can race with split, move or reconnect** → fence by lease and tab ancestry and fall back to a loading/error state until a matching current layout arrives.

## Migration Plan

No service data or protocol migration is required. Read existing pane-keyed local window geometry as a one-time fallback for a tab window, then save it under the stable connection/workspace/tab key. Rollback can ignore the new browser geometry entries; Herdr pane state and sessions are unchanged.

The primary agent integrates the shared shell control, window registry and Tree portal transitions after the interfaces are agreed; only one agent writes a shared source file at a time.
