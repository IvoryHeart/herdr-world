# Terminal debugging knowledge pilot

Limit the initial wiki to quickstart plus terminal identity/visibility and view
navigation. Explain source-backed ownership, the path from authoritative host data
to terminal rendering, and how Spaces, Office, Graph and Tree select/open a terminal.
Follow relevant callers and focused tests; do not generate a whole-repository wiki.

OpenSpec describes intended contracts. This wiki explains implemented behavior and
links to docs/knowledge-map.md and the appropriate current specs. A discrepancy is
an investigation finding, not permission to rewrite a contract.

Use only repository source and synthetic examples. Exclude runtime state, local
configuration, native transcripts, metrics, screenshots and private task notes.
Do not claim the owner's missing/switching terminal bug is reproduced until its
actual steps and observed behavior have been checked.

Generate pages through the upstream OpenWiki page/Claims lifecycle. Finish knowledge
generation before editing product source. After the fix, update affected Claims and
pages against the new source. Record generation/update usage separately from debugging.
