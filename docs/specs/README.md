# Historical specifications

Current contracts live in [openspec/specs](../../openspec/specs).
Start with the [knowledge map](../knowledge-map.md) for source ownership and historical links.

Numbered documents preserve earlier decisions and delivery evidence. Do not start another
numbering, mandatory extension, or paired-summary sequence. Update or supersede the current
contract when direction changes; Git history is the audit trail.

Use an OpenSpec change when the owner asks for one or a new product/API contract needs
a decision. Routine fixes, refactors, dependencies, tests, docs and release mechanics
can proceed directly. Existing authorization continues across planning and implementation.
See [agent development](../agent-development.md).
