# Herdr World 0.3.6: full change list

Every change in 0.3.6, moved unchanged from the release's [changelog](../../CHANGELOG.md) section, which summarises it.

## [0.3.6] - 2026-11-24

### Added

- Draw on Board to brainstorm: pen strokes, rectangles, ellipses, diamonds,
  text and arrows that attach to cards, notes and other drawings, with select,
  move, resize, colour, fill, delete, undo and redo. Drawings are saved with the
  board beside notes and strings; a phone shows them and keeps its notes.
- Apartments residents show their own week of usage (time at work, waiting
  on you, tokens, or that it is not available, or unknown and why), and in Town the
  line opens Usage's Breakdown filtered to that agent, with a chip to show
  every agent again. An agent that left into a shell keeps its usage even
  after the next agent ran in that terminal.
- Focus sessions: hold chimes, notifications and the tab and app-icon count on
  every device for 25, 45 or 90 minutes or until stopped, then get one chime
  and a "While you focused" recap. Start from the Town ring, the board, Menu
  or the command box; the service keeps the session and ends it on its own.
- See what agents made: reports, documents, pages, images and published links
  from Claude Code and Codex agents live in the Library's new **Made by
  agents** tab, filtered by agent or project, found by its search and read in
  its reader, with **Open in Files** and **Open link**. They stay after the
  agent has gone. Desk cards, Town peeks and Chat show a short **Made**
  summary that opens the Library on that agent, Chat shows a small card for
  each one in the turn that made it, and Town's Library sign counts them.
- Apartments residents show their avatar, as live agents do: their Town
  character on their terminal colour with their harness's icon, in the list
  and in the opened resident. A resident without a kept avatar shows the
  nearest: its profile's look, a profile of the same harness, or World's
  default.
- **What can I do here?** and the Town Master's **What's new** list
  Apartments, with a picture of its sign and **Try**, which rings the sign; off camera, Town flies to it instead of
  scrolling.
- Apartments: an apartment building in Town holds every agent not running
  now, asleep and resumable: agents found in each connected host's Claude,
  Codex, Pi and Oh My Pi histories (including those from before Apartments),
  and agents whose terminal ends or that the bus takes. Search residents by
  name, project, summary, pull request or date, read their history, resume
  Claude and Codex agents into a room, or evict them for good. Board's hub
  and the town center ring open the same residents.
- Add a typed Board element registry and CLI/API for durable memory-file,
  saved log/transcript, document and link references with bounded source reads.
  Board presentation follows separately.
- Help for the Code view: a **Code** tab in **What can I do here?** with how
  to pick a project and open its IDE, pictures of the Code view on desktop
  and phone, and **Try**, which switches to Code and rings its project
  picker. **?** in the Code view opens that tab.
- Code view (`/code`, beside Town, Board and Desk): the complete VS Code of
  the host a project is on, inside World on its own address, with your
  extensions, settings and profile there. For a project on an SSH host World
  starts that host's installed `code serve-web` (or code-server / OpenVSCode
  Server) through the connection's OpenSSH destination and forwards its
  private Unix socket; nothing opens a TCP port or another origin, and nothing
  opens an IDE on a desktop. The workbench fills the view under one thin bar;
  the rail of the project's agents and terminals folds away and starts folded
  on narrow windows. VS Code's light or dark follows World's theme (or
  the system's when World follows it) and switches live with it. Stock VS Code's webviews (Markdown preview, some
  extension panels) stay blank inside World, and Microsoft's VS Code opens
  only when World is on HTTPS or localhost: on a plain-HTTP address the view
  says so and what to do instead of waiting. When VS Code can't download its
  web server, World stops waiting and says what it needs. Each IDE is an
  integration (also in Settings → Integrations): detected when installed, with a download link
  and program path when not, and a trust and licence dialog before first
  enable. World starts a server only when you click Open and reuses it per
  project folder. A server keeps running, with its terminals and tasks,
  when you close the view, World restarts or updates, or the SSH link
  drops; World finds it again and reattaches. Code and Settings →
  Integrations list every running IDE server with since-when and Stop, also
  after a restart and on a host whose connection was removed (with the
  command to stop it there). Only pressing Stop on a server stops it, after
  a warning, and that ends its whole process tree on World's computer or the
  SSH host, terminals that left the tree included; disabling the IDE,
  removing the connection or reaching the limit of four stops none. A Stop
  cut off on its host keeps the server listed until you stop it again.
  code-server's port proxies are off.
- **What can I do here?** answers on every screen: the **?** beside the views,
  the phone views menu, **Menu**, Board's **⋯** and Chat's **⋮** open help for
  Town, Board, Chat and everywhere, each entry with a picture and **Try**,
  which shows you the control.
- After an update the Town Master's greeting shows what is new, each with a
  picture and **Try**; a first visit shows a short **Start here** path.
- The website and `docs/HELP.md` have a help page with the same entries.
- Group runtime connections under local or SSH hosts, discover all integrated
  runtimes on connect or request, and retain empty hosts with installation choices.
- Expose host and runtime status in aggregate snapshots, Integrations and the CLI,
  preserving existing runtime IDs, generations and per-connection API arrays.
- One **Integrations** screen (Menu → Integrations) lists runtimes, GitHub,
  Jira, usage metrics, agent skills and the vault, each with what it gives
  World, its state (connected, available, needs connect, error) and one
  Connect or Disconnect. **All**, one tab per kind and a **Vault** tab, with
  counts, and one search that always covers everything keep it usable at
  dozens of integrations; `?integrationsFixture`
  previews that size. Elements missing a source offer **Connect**, which
  opens it at that row. The registry is read-only at
  `GET /api/world/integrations`.
- Browse documented memory and instruction sources for OpenCode, GitHub Copilot
  CLI, Cursor, Qwen Code, Droid, Kimi, oh-my-pi, Kilo, Hermes, Qoder CLI,
  Antigravity CLI, Grok, Devin and Mastra Code, including read-only MDC rules.
- See and manage what each agent and project remembers in the Library: a Town
  building (a sign on phones), with entries from the town center, Board's hub and
  agent settings, and in Settings. It shows what an agent loads at start or when needed, file size,
  age and sharing, and lets you search, read, edit, add and (after confirming)
  delete memory on its owning host.
- On a phone, the corner view menu offers **Hosts**: the same Hosts filter
  and **Manage connections** as the top bar, one tap away without leaving Zen.
- Town's search finds the post office ("post office" or "pull requests") and
  takes the map to it.
- Gate release tags on the exact packaged build walking real Herdr TUI and
  herdr-core, real Claude and Codex startup, prompt delivery, runtime listing,
  upgrade preservation and native service removal on Linux and macOS. Require
  signed-in local Chat reply evidence and publish the tested Unix archives.
- Read-only Shipyard API and CLI for GitHub releases, tags, main workflow health,
  commit-qualified waiting changes and private local World instance observations,
  with explicit stale/limited states and offline synthetic demonstrations.
- Town harbour at the town's right-most edge, on open sea, with one
  colour-coded shipping lane per project: main's checks in each lighthouse,
  merged changes waiting on the slipway, releases as ships and the Worlds
  running them, with links only. A phone's Town has the same harbour right of
  its buildings, and a Shipyard signpost on the town center flies there.
  Work → Releases shows the same per project;
  `?shipyardFixture` (and `=many` for more projects than lanes) shows
  synthetic states for testing.
- Town: a host entering the town rises out of its lot, and one leaving sinks
  into it, while the neighbouring buildings, roads and camera settle into the
  new layout. Reduced motion swaps them at once.
- Town's help has a **Quiet agents** card: what the hourglass on a working
  agent means, the Town board's "N quiet 10 m+" line under Busy that finds
  each one, and the Settings entry for the threshold. **Try** opens the board
  and rings that line.
- Mark a Town agent that is working but whose session has not moved for 10
  minutes: it sits still under an hourglass showing how long it has gone
  quiet, beside its step's running time; its card says how long, and the
  Town board's "N quiet 10 m+" line under Busy finds each one. Settings →
  **Quiet working agents** changes the threshold or turns it off.
- Settings → Town & views → Rooms per row: Auto (the default) keeps each Town
  building about square, a little wider than tall, so a machine with many rooms
  is no longer a tall two-column tower; 2, 3, 4 or 5 sets every building and
  applies at once. Phones keep three compact rooms per row on Auto.
- Town shows the weather: clear, cloud, rain, snow, fog, storm and wind, by
  day, dusk and night, following the Weather source or a condition you hold.
  The sky button under **ALL** opens a Sky panel for the time of day and the
  weather, with a link to the Weather source. Calm and reduced motion show
  still weather; with no weather Town looks as before.
- Read local usage analytics by agent, Git project, room and UTC day through the
  API and `herdr-world usage`, with observed status time, known PR counts,
  explicit unknowns and an offline synthetic example.
- Collect numeric harness usage on Unix core hosts through the same bounded
  reader as TUI hosts; deduplicate connections known to share a transcript host.
- Town has an observatory right of the library: each harness's 5-hour and
  weekly budget used with reset times, a lit window per agent at work, and on a
  phone a folded sign. It opens Usage, with budget pace, runs at once by hour
  (building vs reviewing and checking, counted as true overlap) and tokens by
  run, role, item and project, flagging likely waste such as repeated fixer
  rounds or a nearly full context.
- Usage has a Breakdown tab: time at work, time waiting on you, tokens, cost and
  pull requests opened and merged per agent, project, room and day, with
  "unknown" where World has no reading.
- Harnesses whose logs World does not read still show their runs and the time
  World measured; tokens and cost say they are not available.
- An agent's peek and hover card show its run's role, item, tokens, calls and
  largest prompt, or World's time for harnesses without a log.
- Usage analytics can group by run, with role, branch, pull request (and how it
  was linked), calls, largest prompt and working spans. `?usageFixture` tries
  rare states.
- Add an opt-in Open-Meteo Weather source with one manually set or explicitly
  shared coarse browser location, bounded cached conditions, a shared API/store
  and `herdr-world weather` CLI. Weather failures leave World running; Town
  visuals are separate.
- Browse, search and explicitly manage agent/project memory through one local/SSH
  service, API and CLI, with Claude, Codex and Pi adapters, sharing and age metadata,
  bounded reads, revision checks, confirmed deletes and a synthetic CLI demo.

### Changed

- Tapping a Town table opens its default pane: its one pane, else the focused
  one, else an agent that needs you, else the most recently active one. Only a
  crowded table with nothing focused still asks which pane. On a phone one tap
  opens it; the table's card comes first only when there is nothing to open.
- Town's board folds into a compact status chip with the attention count; hover
  or tap it to open the board as a popover.
- New room offers the host's recent folders, defaults to the most recent one
  (else home), browses subfolders and completes a typed path with Tab.
- Reduce CI contention with parallel core model controls, concurrent static and unit lanes, precise native inputs, shared macOS installer/launchd runners and exact-input checker/film caches. Reuse owned core checkers and generate targeted replay witnesses after exhaustive fault checks.
- Check PR description and changelog policy before pushing, and report bounded CI and delivery measurements with `bun run ci:health`.
- Town's post office is now the place for what is addressed to you: its sign
  counts what Needs you lists (questions, blocked agents, finished work to
  review) and the Outbox's answers to check, and opens Needs you. On a phone
  the sign folds to a smaller plate across the post office's front.
- The phone's warehouse sign on the town center no longer shows pull request
  counts on its face; its list keeps them.
- The post office and the town center are redrawn in the outlined style of
  Town's agents and desks.
- The Weather source's place and on/off are a row in Settings, **Weather place
  and source**, found by Settings search and Cmd+K (**weather**, **location**).
  Town's sky button keeps the quick weather choice and links to that row.
- Change Board surface, Board pulses and Town lens directly from Settings or Cmd+K, with open views updating immediately.
- Use one synced Town master for Town and Board docking; migrate an existing browser name once and remove the retired name setting.
- Needs you shows the questions another World instance on the same runtime
  holds, when both share a local instance registry. Answering or dismissing
  one closes it in that World, exactly once; the answer still reaches the
  agent through that World's own connection.
- An owner alert now says which World holds the question. A World that cannot
  read that question shows "Asked in <World>" with a link instead of nothing.
- Click or tap a Town place's building, not only its sign, to open it: the
  post office, library, Apartments, observatory and warehouse. Hovering a
  building lights its sign.
- Town's places now open in one window: centred over dimmed Town with the same
  header and close button, scrolling inside, and a sheet from the bottom on a
  phone. The post office opens Needs you in it, and the warehouse opens
  Integrations in it while GitHub is off.
- Town shows one building per machine: this computer's Herdr TUI and
  herdr-core rooms stand in one building, each room tagged with its runtime
  and keeping all its own controls. Settings → Town & views → Town buildings →
  One per runtime keeps a building per runtime, as before.
- Board's hub uses plain names: **Past sessions** (with how many finished
  agents) and **Memory** instead of Town's Apartments and Library. Town keeps
  its building names.
- The Hosts filter lists one row per machine instead of one per runtime: a
  computer running both Herdr TUI and herdr-core appears once, its status
  summarises both (for example "1 of 2 reconnecting"), and unchecking it hides
  both runtimes' rooms, even when it is the only machine (the menu then
  reads No hosts). Saved selections map to their machine.
- World serves its web files brotli- or gzip-compressed and lets the browser
  keep them cached, so Town and the other views open faster, and repeat visits
  load them from the browser cache.
- Town shows a room's runtime as a small icon before its name (a terminal
  window for Herdr TUI, a diamond for herdr-core) on plaques and room cards,
  with the runtime's name on hover, focus or tap; move menus name the runtime
  only where two rooms would read the same.
- A room's plaque stands above the room, so every agent of the top row stays
  clickable, and its card opens on a click or tap of the title (Enter or
  Space) and closes on a second click, a press outside or Escape.
- One **Group runtimes** setting, under Settings → This World, now groups a
  machine's Herdr TUI and herdr-core the same way in Town, the navigator,
  Desk and Board, and is shared by every browser. With **One per machine**
  (the default) the navigator shows the machine once with a row per runtime,
  and Board shows one zone for it with a row per runtime. It replaces Town's
  own Town buildings setting; a browser's earlier choice carries over unless
  another browser has already saved one.
- The bin's countdown now comes from Town's bus: its speed (36 km/h) and the
  route past the stops where agents wait and back. The countdown reads when the
  bus is back at Apartments, and an agent at a farther stop gets a longer time.
  The bus sets off a minute after the first agent starts waiting, instead of
  every four minutes. A plate over the bus shows its speed and how far it has
  to drive. Town and the bin in every view show the same time.
- An agent dropped on a Town bus stop now waits at that stop instead of the
  one nearest its room, and the bus calls at every stop with someone waiting
  before it goes back to Apartments.
- Keep all dependency manifests monitored and automatically prepare dependency PR
  notices and changelog metadata; update the isolated verification tools safely.
- The separate Sources and OTEL economy metrics menu entries are replaced by
  Integrations. Tokens go through one vault; the existing Jira token file is
  still read.
- Give Settings → Integrations a finished look on desktop and phone:
  product marks on every row, coloured state chips, actions kept beside each
  row, quieter kind tabs with the Vault set apart, each kind's action on its
  heading, and calm empty and search states.
- Apply connection CLI additions, removals and default changes through the running
  service without restarting it or dropping other hosts' terminals and browser
  sessions. Concurrent Settings edits are retained; `--restart` remains optional
  on loopback and still saves and restarts a managed service bound to one other
  address. Unreachable services retain offline editing; persistence failures
  report service errors rather than usage errors.
- On a phone, Town shows the post office as the same building and parcel
  yard as on a wide screen, beside the town center, with a sign that reads
  "POST OFFICE" and "pull requests"; tapping it opens the parcel list. The
  city expenses billboard also stands above the town center instead of folding
  to a sign.
- One Settings home and one search replace the old Menu and the Configuration
  dialog on desktop and phone. The Menu now lists Settings, Find or act, Zen
  mode, Help, Upgrade (when offered) and Log out (when signed in); every
  setting and command moved into Settings. Cmd+K changes settings from a
  result (try "night" or "font size"), Settings finds the command box's
  commands and view-only controls (Board surface, Town lenses, Manage
  connections), and `?setting=<id>` links open Settings at one setting. Old
  `?settings=next` links open World as usual.
- Open pull requests moved from the post office to Town's new warehouse on the
  harbour's shore, as crates, on a phone too; Town's search finds them as the
  **Warehouse** ("warehouse" or "pull requests"); `?townPostFixture` is now
  `?townWarehouseFixture`.
- Shipyard's lanes are now the projects open in World's rooms and spaces, one
  per GitHub repository, instead of repositories suggested from GitHub. They
  follow projects as they open and close, fill in as each read lands, and list
  open folders without a GitHub remote instead of dropping them, on Unix and
  Windows runtimes.
- Run native plugin assertions with their platform installer jobs, reuse verified
  content-matched CI evidence and builds on pull requests, and schedule nightly
  installation, visual and latency checks while main keeps its full fresh matrix.
- Exercise release-built browser startup with an older profile, background/resume
  and worker activation; retain recorded protocol vectors and rebalance browser
  shards using measured file durations with two independent files per runner.
- Isolate Town's browser launcher action from preceding room hover cards and
  catalog layout shifts; balance its shard using the passing hosted duration.
- Guard the lighthouse check against partial release reads and offer three
  consecutive fresh World browser passes with separate per-pass evidence.
- Town's bus lives at Apartments and drives only the town's roads, by the
  nearest way round the stops with riders and back, instead of driving in and
  off the map. It turns its corners, slows to each stop and opens its door;
  back at Apartments its riders step off and walk in, and the sign counts each
  one as it goes in. The bus is redrawn, and Apartments has its own stop.
- The town center's ring is shorter: places with a building (Apartments,
  Library, the post office's Needs you, the observatory and the warehouse)
  move into a second ring under **Buildings**, and first-ring entries show no
  counts. The second ring opens around Buildings; Back at its centre,
  Escape or a phone's Back return to the first ring. Every label sits
  outside its ring, beyond its icon; a narrow phone's ring is an upright
  oval so its side labels fit.
- Town's post office carries mail: each open question for you is a letter in
  its yard (click one for its card and **Answer in Needs you**), and the mail
  trolley carries your answers on their way and opens the Outbox, on a phone
  too. `?townPostFixture` shows synthetic letters (`=many`, `=empty`).
- The time-of-day button under **ALL** now opens the Sky panel instead of
  cycling through times.
- Town's lights follow where agents are: a room is lit while an agent works
  at a desk there, the bar is lit while anyone is in it, and lights change as
  agents sit down or stand up rather than ahead of the walk.
- Cmd+K (Ctrl+K) finds agents on every host and runtime from every view,
  Spaces and the phone's Find or act included, by name, room, machine,
  runtime, harness, status or task. Enter opens the agent's terminal in
  Spaces on its own connection, herdr-core agents included; in Town, Board
  and Desk, Shift+Enter or the row's Show button selects it there instead.
  Agents on offline hosts stay listed and say why they can't open.

### Fixed

  save it as World's default connection.
- Remove legacy World login services during uninstall while preserving
  herdr-core's login item and unrelated services.
- Tapping a live herdr-core table or pane opens its terminal or Chat instead of
  showing "World can't mark core work reviewed yet".
- herdr-core rooms can be created in a chosen folder, a Windows host's drive or
  UNC folder too; their terminals start there.
- Serialize expensive Town browser cases within each shard so software rendering does not compete with another Town fixture's clock.
- Include red final reruns in CI health samples, and check stacked PR policy against its actual immutable base.
- Commit synthetic SQLite fixture initialization once, retaining full durability for replayed operations while avoiding per-setting fsync bottlenecks.
- Keep the appearance close-churn capacity regression on the real store with a memory backing, avoiding thousands of unrelated durable file flushes.
- Initialize Ranger replay databases from a production-created empty seed while replaying every real SQLite save, rollback and reopen within the original deadline.
- Starting a terminal or agent on a herdr-core host opens its window on the
  first click, as on Herdr TUI hosts, instead of needing more taps on its desk.
- Keep concurrent Claude limits readings from decreasing when a status line
  writer pauses before publishing. Recover locks only after confirmed process
  death, while preserving the bounded wait and the user's status output.
- Find headless Codex and Claude conversations on herdr-core from live process
  session records or writable conversation files, locally and over SSH, without
  guessing the newest transcript in a directory.
- Town now moves herdr-core agents between desks and moves whole desks
  between rooms by updating terminal placement labels, including app spaces
  and World-created rooms. Programs keep running; unavailable operations
  have specific visible reasons, and partial moves are reported honestly.
- Keep every refused Board drawing text draft when a save conflicts with another

- Let a verified terminal withdraw its World questions after a runtime restart,
  keep repeated open-question cap refusals silent with wait guidance, and add
  one-step dismissal of an asker's whole backlog in Needs you.
- Town's bus stop clocks and the bin now always show the same countdown: the
  time until the next bus sets off, ticking together. A stop's clock used to
  count to the bus reaching that stop, on its own timer.
- The Shipyard harbour shows one lane per project that has a published
  release, with no empty piers, vertically centred on its side of Town, and

- Alert the owner when a herdr-core agent asks a question while the default

  Needs you says World did not alert you.
- Say in the Code view why an IDE didn't open and on which computer, and offer
  **Try again** and **Choose another IDE** on every failure (not installed,
  stopped, can't open here, needs a secure address). **IDEs** in the Code
  view's bar shows the IDE list (Enable, Disable, Connect) at any time.
- Show a healthy herdr-core host as live on Board, with its **+** (New
  workspace), instead of **Stale · Reconnect**; strings to its agents stay

- Two Herdr TUI connections to the same socket (the startup default and a

- Focusing a far-off room from the keyboard no longer leaves Town blank: the
  view no longer scrolls the town out of sight.
- Keep VS Code loaded in the Code view while Town, another view or Spaces is in

  Code says so.
- Run the advisory Town golden-image report automatically again: the fixture now

- A Codex agent started on a herdr-core host shows ready (idle) as soon as its

- A large, animated Town no longer leaves its keyboard and screen-reader
  targets unfinished for seconds on a slow machine.

### Known issues

- Concurrent offline connection edits can acknowledge success while losing an
  addition (#1084). Live CLI and Settings edits use the service's serialized queue.
- A Claude limits tap suspended across stale-lock recovery can overwrite a
  newer reading (#1086). The verification inventory retains its counterexample.
- Codex on Linux core stays unknown when the core/harness supplies no native
  status. Current Linux core 0.1.21 / Codex 0.167.0 reports work; World cannot
  reconstruct missing reports from Chat or Terminal output.
